## 1. Research Question

Across the eight IDE/agent ecosystems Kramak targets — Google Antigravity, Cursor, Claude Code, Windsurf, Cline/Roo Code, GitHub Copilot Workspace, Aider, and the Generic fallback — which native planning, subagent/multi-agent, and workspace-isolation capabilities now exist natively, and to what degree do they make an external orchestration layer redundant? Where native primitives remain, how divergent are they, and what does that divergence imply for (a) how Kramak should architect multi-agent execution compatibility, and (b) the maintenance burden of an 8-adapter portfolio maintained by one person?

**Confidence note:** rated Medium, not High. Three of the eight named targets underwent identity-level change (rebrand, shutdown, or brand supersession) inside the three-month lookback window, one shared standard (MCP) shipped its largest-ever breaking revision three weeks before this scan, and at least one load-bearing claim (Claude Code's native `AGENTS.md` support) has directly conflicting secondary-source evidence that this report was unable to fully resolve against first-party documentation. Confidence is High on claims sourced directly from `code.claude.com`, `docs.github.com`, `zed.dev`, `modelcontextprotocol.io`, and the Linux Foundation; Medium-to-Low on claims that rely on secondary reporting for non-Anthropic products, since none of those vendors were fetched from first-party docs at the same depth as Claude Code was.

## 2. Key Findings

- **Three of eight named targets broke identity during the lookback window.** Windsurf was rebranded to *Devin Desktop* by Cognition on June 2, 2026, with the original Cascade agent reaching end-of-life July 1, 2026; Roo Code shut down entirely on May 15, 2026 and pointed users to Cline, Kilo Code, or its own cloud pivot Roomote; and "GitHub Copilot Workspace" has been a dead brand name since May 30, 2025, superseded by Copilot coding agent, Agent mode, and the GitHub Copilot app. An adapter portfolio keyed to 2025-era product names will misfire on three of eight targets today. [Grade A/B — see §7]
- **Native subagent/multi-agent concurrency with git-worktree isolation is now table stakes, not a differentiator.** Six of eight ecosystems ship it, most as GA: Antigravity (`invoke_subagent`, worktree-backed "branch" isolation), Cursor (async subagents within a run, plus parallel background/cloud agents), Claude Code (subagents plus the separate Agent Teams feature), Devin Desktop (Devin Local subagents replacing single-context Cascade), and the GitHub Copilot app (up to 10 worktree-isolated parallel sessions per repo). Aider remains the explicit outlier with zero native multi-agent concurrency; Cline's subagent feature exists but is presently disabled upstream mid-migration.
- **Three cross-tool standards have converged with real governance behind them, but none standardizes the orchestration layer itself.** `AGENTS.md` (OpenAI-originated) and MCP (Anthropic-originated) are now sibling founding projects of the Linux Foundation's Agentic AI Foundation (AAIF, formed December 9, 2025), and Anthropic's Agent Skills/`SKILL.md` format reached 32+ tool adoptions within roughly 90 days of its December 18, 2025 open-standard release. All three cover *static configuration* (rules, tool access, packaged capabilities) — none of them specifies how an agent decomposes a task, how many workers run concurrently, or how workspace isolation is granted. That gap is exactly where Kramak's adapter layer still earns its keep.
- **A fourth, adjacent protocol is a live fork rather than a convergence point.** Zed's Agent Client Protocol (ACP) standardizes *hosting one external agent's UI loop inside an editor* ("LSP for agents"). Zed, JetBrains, and Devin Desktop have adopted it natively; Microsoft has explicitly standardized VS Code's agent surface on MCP instead, and Claude Code reaches ACP clients only through a third-party bridge Zed built, not native support. This is not settled ecosystem consensus.
- **Even the converged layer is still moving.** MCP shipped its "largest revision since launch" as final spec `2026-07-28` — barely three weeks before this scan — removing protocol-level sessions and deprecating Roots/Sampling/Logging under a new 12-month lifecycle policy. Old-client/new-server (or the reverse) interoperability is not guaranteed without explicit fallback handling. Separately, Claude Code's native `AGENTS.md` support is contested: the official subagent-context documentation this report fetched directly makes no mention of `AGENTS.md`, and a GitHub feature request with 5,200+ reactions (`anthropics/claude-code#6235`) appears to remain open as of the most recent evidence found — despite some secondary sources asserting native support already exists.
- **Release velocity is uniformly high across every proprietary target except Aider.** Claude Code ships near-daily point releases (observed jumping from v2.1.229 to v2.1.233 within roughly two weeks); Cursor, Antigravity, and GitHub Copilot ship weekly-to-biweekly changelog entries. Aider remains 0.x-versioned with breaking CLI-flag and `.aider.conf.yml` changes across minor releases — slow-moving in feature surface, but not contractually more stable.
- **The rules-file surface has converged harder than any other layer.** Seven of eight targets now read `AGENTS.md` natively or near-natively, and GitHub Copilot will fall back to a bare `CLAUDE.md` or `GEMINI.md` if no Copilot-specific file exists. A single well-authored `AGENTS.md`, layered with thin tool-specific overlays, now covers most of the portfolio's "custom instructions" requirement — this is the highest-leverage, lowest-maintenance investment available to Kramak.

## 3. Recommendation

**Headline: shrink the adapter layer's footprint, don't retire it.** Treat `AGENTS.md` + MCP + `SKILL.md` as a capability floor every target gets close to free; reserve hand-written adapter code for the orchestration-layer differences (subagent dispatch, isolation semantics, concurrency limits, inter-agent messaging) that remain genuinely proprietary and where native primitives now equal or exceed what a thin external wrapper could do safely.

### 3.1 Architecture: a capability-tiered adapter model, not a flat 8-adapter list

Replace the implicit assumption that all eight adapters carry equivalent scope with three explicit tiers. Each target is assigned a tier based on current evidence, and — critically — every adapter should be able to **degrade gracefully to the tier below it** when a native API breaks, rather than failing outright. This directly addresses the maintenance-burden question: a breaking change in a proprietary orchestration endpoint should downgrade an adapter to "rules-only," not take it offline.

- **Tier 0 — Generic baseline (every target, near-zero bespoke code).** Emit `AGENTS.md` at the repository root and wire MCP servers via the target's native MCP config surface. This is now sufficient to be *read* by seven of eight ecosystems and is the correct default output regardless of which deeper tiers apply.
- **Tier 1 — Rules-and-context adapters (thin, low maintenance).** Kramak's job is only to emit the right filename, location, and frontmatter shape for a tool that has no meaningfully differentiated orchestration surface worth mapping. Aider (`CONVENTIONS.md` / configured `AGENTS.md` load) and, for now, Cline (`.clinerules/`) and the Generic fallback belong here. GitHub Copilot's instruction-file surface (`.github/copilot-instructions.md`, `.github/instructions/*.instructions.md`) is Tier 1 even though the underlying product also has Tier 2 capability, because the instructions surface is the stable part.
- **Tier 2 — Orchestration-aware adapters (where native subagent/worktree primitives are GA and worth mapping to).** Claude Code (subagents + Agent Teams), Cursor (Agents Window, background/cloud agents), and — with the caveats in §3.3 — Antigravity and Devin Desktop (ex-Windsurf) and the GitHub Copilot app's worktree-isolated parallel sessions. Here Kramak should translate its own task graph into the tool's native dispatch call rather than shelling out to a separate orchestration process.

### 3.2 A minimal multi-agent integration primitive set

Define one small intermediate representation (IR) inside Kramak that every Tier-2 driver translates from, rather than writing eight bespoke task-decomposition engines:

| IR primitive | Claude Code mapping | Cursor mapping | Antigravity mapping | Devin Desktop mapping |
|---|---|---|---|---|
| `task` (unit of work + prompt) | `Agent` tool invocation / subagent definition | background/cloud agent session | `invoke_subagent` call | Devin Local subagent spawn |
| `isolation-mode` (shared / branch / worktree) | `isolation: worktree` frontmatter field | worktree, remote SSH, or cloud sandbox | workspace option: `inherit` / `branch` / `share` | worktree via Agent Command Center / Spaces |
| `concurrency-budget` | `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (default 20) | queue/multitask behavior | no documented hard cap found | no documented hard cap found |
| `dependency` (task B waits on task A) | manual chaining / resume-by-agent-ID via `SendMessage` | `Await` tool | sequential subagent invocation | coordinator/subagent result feed |

Kramak should not attempt to standardize *concurrency semantics* across tools (the differences — e.g., Claude Code's documented depth-3 nesting default and 20-way concurrency cap vs. Cursor's queue-based multitasking — are real and load-bearing) but should standardize the *authoring surface* a Kramak user interacts with, so switching target tools doesn't require re-authoring task graphs by hand.

### 3.3 Adapter prioritization

| Priority | Target(s) | Rationale |
|---|---|---|
| **P0 — maintain deep Tier-2 mapping** | Claude Code, Cursor | Largest documented, versioned, first-party orchestration surfaces; both GA (not preview-gated); both have stable-enough primitives (worktree isolation, subagent frontmatter/API) to justify real engineering investment despite high release velocity. |
| **P1 — maintain, Tier-1 now / re-evaluate Tier-2 quarterly** | GitHub Copilot (as *coding agent* + *Copilot app*, not the dead *Workspace* brand), Windsurf/Devin Desktop | Both have real Tier-2 capability (worktree-isolated parallel sessions; Devin Local subagents) but both are under two and a half months old in their current form as of this scan. Track them at the rules/MCP layer now; add orchestration mapping once each has one full quarter of post-launch stability data. |
| **P2 — Tier-1 only, defer Tier-2** | Google Antigravity, Aider | Antigravity's core subagent/worktree feature is GA, but the product itself still ships under preview terms and its most advanced orchestration primitive (Multi-Agent Teamwork) is explicitly preview-and-paywalled — poor ROI for a solo maintainer to build against right now. Aider has no Tier-2 surface to map to at all; further investment there should go to config-format stability tracking, not orchestration. |
| **P3 — Tier-1 minimal, do not chase Tier-2** | Cline | Cline's subagent feature is mid-migration and reported disabled upstream during its SDK 2.0 stabilization. Keep the `.clinerules/` emitter alive; do not invest engineering time in subagent mapping until upstream re-enables and documents the feature. |
| **Retire as a named target** | Roo Code | The product is discontinued (May 15, 2026). Do not maintain a dedicated Roo Code adapter. Existing Roo-shaped output (`.roorules`, `.roo/rules-{mode}/`) should be produced only as a courtesy fallback for stragglers on the archived extension, generated from the same Tier-1 templates as Cline, with no new feature investment. Reassess whether a Kilo Code adapter is warranted only if usage telemetry shows meaningful demand (see §6, risk 6). |
| **Baseline, elevate in priority** | Generic fallback | Should not be thought of as "the tool for unsupported targets" but as the Tier-0 output every adapter produces first. Its main risk is now identical to `AGENTS.md`'s own governance risk (Grade A — AAIF-backed), which is currently the most stable single dependency in this entire portfolio. |

This ordering directly answers the "is native tooling making external orchestration redundant" question asked in the brief: **for Aider and the rules-only layer of every tool, yes — a thin config emitter is now strictly sufficient. For Claude Code, Cursor, and (cautiously) Antigravity/Devin Desktop's deeper primitives, no — native subagent APIs are powerful but tool-specific, so a translation layer still adds real value, provided it is architected to degrade rather than break.**

## 4. Alternatives Considered

- **Maximalist — deep bespoke integration against every native orchestration API.** Rejected as the default posture. Given that three of eight targets had an identity-level break within one quarter, and that even Claude Code (the most stable, best-documented target) ships near-daily, betting deep integration effort evenly across all eight targets is a poor risk-adjusted use of a solo maintainer's time. Retained selectively for the P0 tier only (§3.3).
- **Minimalist — retire per-tool adapters entirely and ship only the Generic `AGENTS.md` + MCP baseline.** Rejected as under-serving the brief's explicit ask about multi-agent execution compatibility. This would leave real, GA, well-documented orchestration value (Claude Code subagents/Agent Teams, Cursor's Agents Window) unused for the two highest-usage, most-stable targets, where the native primitives are mature enough to be worth mapping to.
- **Standardize exclusively on Agent Client Protocol (ACP) as a universal hosting layer.** Rejected. ACP solves a different problem — embedding one external agent's UI inside an editor ("agent-to-client," per Zed's own framing) — not multi-agent task decomposition or concurrent worker orchestration. Adoption is also still split (no native VS Code/Copilot or Claude Code support), so it cannot yet serve as a universal layer even for the narrower problem it does solve.
- **Freeze adapter development pending further ecosystem consolidation.** Rejected, but informs the recommended posture rather than being discarded outright. The convergence signals in §5.3 (AAIF governance of `AGENTS.md`/MCP, rapid Skills adoption) suggest the standards layer is stabilizing *now*; waiting forfeits the current low-cost window to build the Tier-0/Tier-1 baseline on a foundation that is unlikely to get simpler. The tiered, degrade-gracefully model (§3.1) captures the risk-reduction benefit of "wait and see" without fully halting development.

### 5.2 Per-Tool Profiles

#### Google Antigravity

Announced November 18, 2025 as an "Agent Manager" bundled with a VS Code–derived IDE; relaunched as **Antigravity 2.0** on May 19, 2026 as a four-surface product family — a standalone desktop app, the original Antigravity IDE, an `agy` CLI, and an SDK — built around Gemini 3.x models with Claude and open-source model options also selectable. **[A]** The product is still labeled a preview release in its own version metadata as of the most recent third-party build tracking found, and access remains free during preview with a personal Google account. **[B]**

- **Planning/task breakdown:** Task-level "Artifacts" (plans, diffs, browser recordings, verification reports) give async, unattended visibility into what an agent did; scheduled/cron-style tasks let agents run unattended and report back the next session. **[A]**
- **Multi-agent & isolation:** Subagents are **GA** and invoked via an `invoke_subagent` tool with three explicit workspace options — `inherit` (shared workspace), `branch` (isolated git worktree, auto-provisioned and auto-cleaned), and `share` (shared directory storage). **[A]** A distinct **Multi-Agent Teamwork** capability (`/teamwork-preview`), which adds automatic error recovery and cross-agent task coordination, is explicitly labeled preview and gated to the $200/mo Ultra plan only — this is the clearest GA/preview split in the entire scan and should not be treated as generally available. **[A]**
- **Rule file format/location/precedence:** Current default is a `.agents/rules/` directory at the project root (12,000-character limit per file), with the earlier singular `.agent/rules/` still honored for backward compatibility. `AGENTS.md` gained native support in v1.20.3 (March 5, 2026); community documentation reports `GEMINI.md` taking precedence over `AGENTS.md` on conflict, though this is not confirmed against first-party docs in this scan. **[B]** Skills use the same `SKILL.md` folder format as Claude Code (added IDE v1.14.2), and Workflows are separate step-recipe files under `.agent/workflows/`, including a `// turbo` comment marker for unattended command execution. **[B]**
- **Release velocity/API stability:** Extremely high. The changelog shows point releases through at least v2.8.1 by mid-August 2026, with a parallel CLI version line at v1.1.14 dated one day before this scan. **[A]** One independent source doing hands-on testing of skill-file discovery explicitly noted Antigravity's own documentation "seems to be out of date" relative to shipped behavior — a direct signal of documentation lag under this release cadence. **[B]**

#### Cursor

Cursor 3.0 shipped April 2, 2026 and is described by Anysphere as the biggest architectural change since the editor's launch: a standalone, agent-first **Agents Window** for running many agents in parallel across repos and environments, alongside Composer 2 (Cursor's own frontier coding model), an integrated browser, and a plugin marketplace. **[A]**

- **Planning/task breakdown:** Composer-driven planning inside the Agents Window; an `Await` tool lets an agent explicitly wait on background shell commands or subagents before proceeding. **[A]**
- **Multi-agent & isolation:** Cursor runs **async subagents within a single agent run** (shipped April 24, 2026) that split larger tasks across a fleet of parallel workers automatically, in addition to longer-running **background/cloud agents** that operate on separate branches, worktrees, remote SSH targets, or Dockerfile-defined cloud sandboxes. Cloud-agent environments gained build secrets, environment version history, rollback, and audit logs by mid-May 2026, and an August 13, 2026 release added pre-warmed "Builds" so agents start from a ready environment rather than provisioning from scratch. **[A]** A cloud subagent can now run without blocking its parent and move between local and cloud execution. **[A]**
- **Rule file format/location/precedence:** `.cursor/rules/*.mdc` — Markdown with YAML frontmatter — replaced the legacy single `.cursorrules` file, which still works for backward compatibility only and receives no new features. Four activation modes: Always Apply, Auto Attached (glob-based), Agent Requested (description-based), and Manual (`@mention`). `AGENTS.md` is read natively and merged with `.mdc` rules rather than competing with them; `.mdc` rules generally carry more contextual weight where content overlaps because of glob/agent-requested targeting. **[B]**
- **Release velocity/API stability:** Very high — near-weekly changelog entries through August 2026, including a new git-hosting product ("Origin," Aug 3), a model-routing layer ("Cursor Router," pairing Grok 4.5 and Cursor's own Composer), and Cursor for iOS remote control. **[A]** Skills, hooks, plugins, and MCP support were all added to the surface area over 2026, meaningfully expanding what a Cursor-specific adapter needs to track. **[B]**

#### Claude Code

Sourced directly from Anthropic's official subagent documentation (`code.claude.com/docs/en/sub-agents`) and changelog. **[A]** throughout unless noted.

- **Planning/task breakdown:** Built-in `Explore` (read-only search), `Plan` (read-only research during plan mode), and `general-purpose` (full-tool) subagents ship by default; `Explore` as of v2.1.198 inherits the parent conversation's model (capped at Opus on the Claude API) rather than always running on Haiku, so a user or project subagent literally named `Explore` is required to force a cheap-model override.
- **Multi-agent & isolation:** Custom subagents are Markdown files with YAML frontmatter, loaded from `.claude/agents/` (project) or `~/.claude/agents/` (user), with managed-settings, CLI-flag, and plugin-provided subagents at other precedence tiers (managed highest, plugin lowest). Nested subagent depth defaults to 3 (this default itself changed twice in 2026 — 5 by default through early in the year, briefly defaulting to 1, then settled at 3 — a concrete illustration of how much even "stable" primitives move); a session-wide concurrency cap defaults to 20 simultaneous subagents (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`). True workspace isolation is opt-in per subagent via `isolation: worktree` frontmatter, which provisions and enforces a dedicated git worktree (including blocking commands that would redirect git back into the main checkout). A separate **Agent Teams** feature coordinates multiple independent Claude Code sessions that message each other directly (mailbox/`SendMessage` pattern) rather than returning a single summary to a parent — distinct from subagents and pitched at workloads needing sustained parallelism or cross-worker communication mid-task.
- **Rule file format/location/precedence:** `CLAUDE.md` hierarchy (`~/.claude/CLAUDE.md` global, project `CLAUDE.md`, `CLAUDE.local.md`, managed policy files), all loaded by every subagent except the built-in `Explore`/`Plan`, which skip it for speed. **Native `AGENTS.md` support is contested** — the official documentation fetched for this report describes only the `CLAUDE.md` hierarchy loading into subagent context, with no mention of `AGENTS.md`, and a long-running GitHub feature request (`#6235`, opened August 2025, 5,200+ reactions per secondary reporting) appears to remain open. Some secondary sources assert Claude Code merges `AGENTS.md` and `CLAUDE.md` automatically; others assert the opposite and recommend an explicit `@AGENTS.md` import line inside `CLAUDE.md` as the supported workaround. This report was unable to fully resolve the conflict and flags it as an open risk (§6). **[B/C — conflicting]**
- **Release velocity/API stability:** The fastest-moving target in this scan. Observed changelog entries jumped from v2.1.229 to v2.1.233 within roughly two weeks, with near-daily patch entries and frequent default-behavior changes (e.g., the concurrent-subagent spawn cap, previously 200 per session, was removed entirely in a recent release). Despite the pace, changes are unusually well-documented — every behavioral change found during this scan was traceable to a specific version number in first-party docs, which meaningfully reduces (but does not eliminate) integration risk relative to less-documented fast movers.

#### Windsurf (now **Devin Desktop**)

**This target's name changed during the scan window.** Cognition AI (maker of the autonomous agent Devin), which acquired Windsurf's team, IP, and brand in 2025, rebranded the product to **Devin Desktop** via an over-the-air update on June 2, 2026; the change was corroborated by Cognition's own devin.ai blog post "Windsurf Is Now Devin Desktop" and by the product's own changelog/UI. **[A]** Plans, pricing, extensions, and settings carried over automatically with no migration step required from users. **[A]**

- **Planning/task breakdown:** The original Cascade agent's flow-aware context engine (file tree, imports, terminal output, errors) carries into Devin Local; an **Agent Command Center** presents a kanban-style board of running, waiting-for-review, and completed sessions across both local and cloud (Devin Cloud) work. **[B]**
- **Multi-agent & isolation:** **Cascade itself reached end-of-life July 1, 2026** and was replaced by **Devin Local**, described by Cognition as a from-scratch Rust rewrite that is up to 30% more token-efficient and, unlike Cascade, natively supports subagents — parallel sub-sessions that can, for example, split a schema migration from its accompanying test-suite work and feed results back to a coordinator. **[B]** Workspace isolation is provided through git worktrees managed by the Command Center/"Spaces" feature. **[B]** Separately, Devin Desktop shipped native support for Zed's **Agent Client Protocol (ACP)**, positioning the editor as an ACP *host* capable of running Codex, Claude Agent (via Zed's bridge), Gemini CLI, OpenCode, and Junie as swappable "guest" agents inside one window — described by Cognition as the strategic core of the rebrand. **[A]**
- **Rule file format/location/precedence:** Legacy `.windsurfrules` (single flat file, no structure) has been superseded by a `.windsurf/rules/` directory format with always-on/manual/glob-based activation modes; `AGENTS.md` is auto-discovered. A separate cross-tool packaging effort (tracked in a public GitHub issue) is actively moving Windsurf/Devin Desktop's skills primitive from a Windsurf-specific path to the shared `.agents/skills/` convention already used by Copilot, Cursor, Codex, Gemini, and OpenCode — an in-progress convergence, not yet finished as of the most recent evidence found. **[B]**
- **Release velocity/API stability:** **Volatile.** Beyond the rebrand itself, this target underwent a full agent-runtime replacement (Cascade → Devin Local) inside a five-week window (June 2 – July 1, 2026). Any Kramak logic keyed to "Windsurf" or "Cascade" naming, file paths, or behavior needs to be re-validated against Devin Desktop / Devin Local before being trusted as current.

#### Cline / Roo Code

**This is now two separate risk profiles, not one.** The brief's pairing reflects a shared ancestry (Roo Code originally forked from Cline) that no longer implies shared status.

**Cline** — open-source (Apache 2.0), now shipping as a VS Code/JetBrains/Cursor/Windsurf/Zed/Neovim extension family plus a CLI, following a May 2026 "Cline SDK" rebuild that decouples the agent runtime from any single IDE surface. **[B]**
- *Planning/task breakdown:* Plan/Act mode separation, allowing different models for planning vs. execution.
- *Multi-agent & isolation:* Subagents exist as read-only, manually-triggered research workers (cannot write files, run destructive commands, or reach MCP servers) — but the project's own changelog states subagents are **temporarily disabled in the VS Code extension while the SDK-backed experience is stabilized**, i.e., the feature is currently non-functional in at least one surface as of the most recent changelog evidence found. **[B]** No native workspace-isolation (worktree) mechanism was found in this scan.
- *Rule file format:* `.clinerules/` directory, file-scoped, version-controllable; `AGENTS.md` is also read.
- *Stability:* GA product, but architecturally in flux mid-migration — treat any subagent-related claim as provisional until upstream confirms re-enablement.

**Roo Code — discontinued.** CEO-announced sunset April 20–21, 2026; the VS Code extension, Roo Code Cloud, and Roo Code Router all shut down May 15, 2026, with the repository archived and the team pivoting fully to *Roomote*, a Slack-first cloud agent operating outside any IDE. **[A — multiple independently corroborating sources, including the project's own sunset announcement reported via The New Stack, plus a downstream deprecation tracked in an unrelated open-source project's own issue tracker.]** Roo's own farewell guidance pointed users toward Cline (for a model-agnostic open-source extension) or a hard fork, **Kilo Code**, which reached GA on April 2, 2026 on a rebuilt OpenCode-server architecture with materially different configuration (`kilo.jsonc` replacing `.roomodes`, a new permissions model replacing tool groups, and Orchestrator mode dropped from the new architecture — available only by pinning the legacy Roo-derived v5.x branch). **[B]** A separate community fork, "Zoo Code," has also picked up the archived extension. **[C]** For rule-file purposes: legacy Roo config used `.roorules` / `.roo/rules-{mode}/` (directory form takes precedence over the flat-file form) plus `.roomodes` for custom mode definitions; Roo added `AGENTS.md`-adjacent (`AGENT.md`) support shortly before shutdown.

#### GitHub Copilot (named "Copilot Workspace" in the brief; **that brand is dead**)

The original **Copilot Workspace** technical preview (launched April 2024) was sunset May 30, 2025. GitHub describes its successor as having absorbed "the sub-agent architecture, the issue-to-PR workflow, and the asynchronous execution model" into the now-GA **Copilot coding agent** (GA since September 2025). **[B]** Since then the surface has continued to fragment and re-consolidate: interactive **Agent mode** reached GA in VS Code and JetBrains in March 2026; a terminal-native **Copilot CLI** reached GA; and a standalone **GitHub Copilot app** — the closest analog to Antigravity's Agent Manager or Cursor's Agents Window — was announced at Microsoft Build (June 2, 2026) as a technical preview and reached general availability June 17, 2026. **[A/B — see §7 for the timeline reconciliation between sources describing preview vs. GA status]** Practically, an adapter should target **Copilot coding agent + the instructions-file surface**, not the literal dead "Workspace" name.

- **Planning/task breakdown:** CLI-level `/plan` and `/review` sub-agents, with `Explore` and `Task` agents invoked automatically for relevant requests; multi-turn follow-up messages can be sent to a running background subagent via `/tasks` without waiting for completion. **[A]**
- **Multi-agent & isolation:** The GitHub Copilot app runs **up to 10 parallel agent sessions per repository**, each automatically provisioned into its own isolated git worktree (local or cloud sandbox) with no manual setup or cleanup required — directly comparable in mechanism to Antigravity's `branch` mode and Claude Code's `isolation: worktree`. **[A]** The app also ships "Agent Finder" for on-demand MCP server/skill/agent discovery and supports bring-your-own-model routing. **[A]**
- **Rule file format/location/precedence:** `.github/copilot-instructions.md` (repository-wide) plus `.github/instructions/*.instructions.md` (path-specific via an `applyTo` glob in frontmatter) are Copilot-native; `AGENTS.md` files anywhere in the repo are also read, with the nearest `AGENTS.md` in the directory tree taking precedence — and GitHub's own documentation explicitly states a single `CLAUDE.md` or `GEMINI.md` at the repo root is accepted as an alternative to `AGENTS.md`, which is a notably generous convergence stance compared to every other tool profiled. **[A]** Custom named agents are defined in `.github/agents/` (repo) or `agents/` (org/enterprise) with YAML frontmatter (`description`, `name`, `tools`, `model`, `target`). **[A]**
- **Release velocity/API stability:** High and multi-surface — VS Code-integration changelogs ship roughly monthly on top of the coding-agent, CLI, and standalone-app release cadences, each with its own version history. The multiplicity of surfaces under one brand is itself a maintenance-relevant fact: "GitHub Copilot" as a named target in an adapter portfolio now spans at least four semi-independent products.

#### Aider

The clearest outlier in this scan: mature, narrowly-scoped, and explicitly **not** pursuing multi-agent concurrency as a design direction. **[B]**

- **Planning/task breakdown:** **Architect mode** splits work between a reasoning/planning model and a separate, typically cheaper, editing model — a two-model *sequential* pipeline, not concurrent multi-agent execution. A community feature request for a more general `/agent` command supporting customizable multi-step workflows beyond the architect/editor pattern has been open since March 2025 without being implemented as of the most recent comparison articles reviewed for this scan. **[C]**
- **Multi-agent & isolation:** None found. No subagent primitive, no native worktree-based isolation; Aider's "isolation" is limited to its git-native auto-commit behavior (every AI edit lands as its own commit unless `--no-auto-commits` is set).
- **Rule file format/location/precedence:** `CONVENTIONS.md` is Aider's own convention but is **not auto-discovered** — it must be explicitly loaded via `--read CONVENTIONS.md` or a `read:` entry in `.aider.conf.yml`. `AGENTS.md` can be configured to auto-load the same way; there is no default zero-config behavior for either file, which is a meaningful divergence from every other tool in this scan (all of which auto-discover their primary rule file). `.aider.conf.yml` itself is loaded from up to three locations (home directory, git root, current directory) with later files taking priority.
- **Release velocity/API stability:** Aider ships at a "steady cadence" per community reviews but **remains 0.x-versioned as of mid-2026**, and multiple independent reviews explicitly flag breaking changes in CLI flags and `.aider.conf.yml` format across minor releases — teams pinning Aider in CI or shared tooling are advised to review the changelog before upgrading. This is a materially different stability profile than "low release velocity implies low risk": Aider changes less *often* than Claude Code or Cursor, but with fewer compatibility guarantees per change. **[B]**

#### Generic fallback

Not a product to profile but a design target: the lowest-common-denominator adapter for any tool without bespoke support, or the degraded-mode target every Tier-2 adapter should fall back to. Its practical content is now well-defined by the convergence findings in §5.3: emit `AGENTS.md` at the repository root, wire MCP servers through whatever native MCP config surface exists (nearly universal at this point), and optionally emit a `SKILL.md`-shaped capability package where a target supports Agent Skills. This tier carries no tool-specific breaking-change risk of its own — its risk is entirely inherited from the stability of the underlying standards (§5.3, §6).

### 5.3 Cross-Tool Convergence Analysis

Three static-configuration standards have converged with real, neutral governance behind them:

1. **`AGENTS.md`** — released by OpenAI in August 2025, contributed to the Linux Foundation's newly-formed **Agentic AI Foundation (AAIF)** on December 9, 2025 alongside Anthropic's MCP and Block's `goose`, with platinum-tier membership from AWS, Google, Microsoft, Anthropic, Block, Bloomberg, Cloudflare, and OpenAI. **[A]** Adoption is reported at 60,000+ open-source repositories and 28+ tools with native support as of mid-2026, including Cursor, Windsurf/Devin Desktop, GitHub Copilot, Aider (configurable), Antigravity, and Codex. **[A/B]** The two live exceptions are **Gemini CLI** (still `GEMINI.md`-first) and **Claude Code**, where native support is contested (§6).
2. **Model Context Protocol (MCP)** — the tool/data-access layer, also now AAIF-governed, reporting 110M+ monthly SDK downloads and 10,000+ published servers by April 2026. **[B]** Critically, MCP is not a static, finished standard: its final `2026-07-28` specification — published July 28, 2026, roughly three weeks before this scan — is described by its own lead maintainers as the largest revision since launch, removing protocol-level sessions, dropping the initialization handshake, and deprecating Roots, Sampling, and Logging under a new 12-month minimum deprecation window. **[A]** Cross-version interoperability between old-spec clients and new-spec servers (or the reverse) is explicitly not guaranteed without deliberate fallback handling, per third-party enterprise-readiness analysis of the release. **[B]**
3. **Agent Skills / `SKILL.md`** — Anthropic's packaged-capability format, opened as a standard on December 18, 2025. Adoption was unusually fast: Microsoft (VS Code/Copilot) and OpenAI (ChatGPT, Codex CLI) shipped support within 48 hours, Google's Antigravity adopted it the following month, and independent tallies put adoption at 32+ tools by March 2026, including Cursor, Windsurf, and (before its shutdown) Roo Code. **[B]**

A fourth protocol sits adjacent but has **not** converged: Zed's **Agent Client Protocol (ACP)**, a JSON-RPC 2.0 standard (Apache 2.0, created June 2025) for embedding an external agent's interactive loop inside an editor UI — explicitly "agent-to-client," not agent-to-agent, and therefore not a substitute for the multi-agent orchestration primitives this report is centrally concerned with. Zed, JetBrains (since December 2025), and Devin Desktop have adopted it natively, with a shared agent registry (co-launched January 28, 2026) listing 50+ agents by late June 2026 — Cursor itself joined the registry as a guest agent in March 2026, a notable signal given it is a competing host. **[B]** But Microsoft has explicitly standardized VS Code's own agent mode on MCP rather than ACP, and Claude Code has no native ACP support — it reaches ACP-speaking editors only through a bridge adapter Zed built and maintains independently. **[B]** ACP also remains local-subprocess-only; a remote-agent transport is on its public roadmap but unshipped as of the most recent evidence found. **[B]**

**Net read for Kramak:** the "what does every tool read for instructions/tools/capabilities" question is now close to solved by three converged, foundation-governed standards. The "how do multiple agents get dispatched, isolated, and coordinated" question remains almost entirely proprietary per tool, with even the closest thing to a shared answer (ACP) explicitly out of scope for that problem. This is the single clearest architectural signal in this scan.

## 6. Open Questions & Risks

1. **Claude Code's native `AGENTS.md` support status is unresolved.** Official documentation fetched for this report describes only `CLAUDE.md`-hierarchy loading into subagent context, with no mention of `AGENTS.md`; a high-engagement GitHub issue requesting the feature appears to remain open. Other secondary sources assert native merge-and-read behavior already exists. *Risk:* if Kramak assumes native support and it is absent, Tier-0 `AGENTS.md` output will silently not load for Claude Code users without the documented `@AGENTS.md`-import-inside-`CLAUDE.md` workaround. *Revisit trigger:* directly check Anthropic's memory/context documentation for an explicit `AGENTS.md` statement, or watch `anthropics/claude-code#6235` for a close/merge event.
2. **Antigravity's preview status could flip to GA at any time, changing the risk calculus for Tier-2 investment.** *Revisit trigger:* an explicit GA announcement on `antigravity.google`, or `/teamwork-preview` losing its "-preview" suffix.
3. **MCP's `2026-07-28` rewrite is three weeks old at the time of this scan; real-world interoperability friction has not yet been widely reported.** *Risk:* Kramak's MCP wiring, if built against 2025-11-25 assumptions, may misbehave silently against newly-updated servers, or vice versa. *Revisit trigger:* track adoption of the new SDK conformance tiers; explicitly test Kramak's MCP integration against the `2026-07-28` conformance suite before the 12-month Roots/Sampling/Logging deprecation window closes.
4. **Devin Desktop (ex-Windsurf) is barely six weeks past Cascade's end-of-life at scan time; Devin Local's subagent model and ACP-hosting behavior are still stabilizing.** *Risk:* any adapter logic written against "Windsurf" or "Cascade" naming or behavior is already out of date. *Revisit trigger:* a Cognition/devin.ai post confirming Devin Local API stability, or a second point release indicating the post-rebrand dust has settled.
5. **Cline's subagent feature is reported disabled upstream during SDK 2.0 stabilization.** *Risk:* any orchestration-layer investment in Cline subagents right now targets a feature that may not currently function for end users. *Revisit trigger:* a `cline/cline` changelog entry re-enabling subagents in the VS Code extension.
6. **Roo Code's succession is fragmented across at least three paths (Cline, Kilo Code, community "Zoo Code" fork) with no clear installed-base leader identified in this scan.** *Risk:* picking the wrong successor to support could strand the portion of Kramak's existing user base that came from Roo Code. *Revisit trigger:* a 6-month comparison of GitHub star/install trajectory across Cline, Kilo Code, and Zoo Code before committing engineering time to any Roo-successor-specific feature.
7. **GitHub Copilot's naming/surface fragmentation (coding agent / Agent mode / CLI / standalone app) may consolidate or fragment further**, the same way "Copilot Workspace" itself did. *Risk:* an adapter tuned to today's surface split could be invalidated by GitHub's next reorganization. *Revisit trigger:* any `github.blog/changelog` entry renaming or merging these surfaces.
8. **Agent Client Protocol (ACP) adoption remains genuinely split** (Zed/JetBrains/Devin Desktop yes; VS Code/Copilot and native Claude Code no), so it cannot serve as Kramak's universal multi-agent hosting layer today. *Risk:* under-investing here forfeits a future universal layer if adoption tips further; over-investing bets on a protocol Microsoft has explicitly not adopted. *Revisit trigger:* a Microsoft/VS Code or Anthropic announcement of native ACP support.
