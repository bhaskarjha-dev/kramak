## 1. Research Question

Should Kramak (a) continue hand-maintaining deep adapters for all 8 IDE/agent targets (Google Antigravity, Cursor, Claude Code, Windsurf, Cline/Roo Code, GitHub Copilot, Aider, Generic), (b) consolidate deep maintenance to a Tier‑1 core plus Generic, or (c) restructure around an `AGENTS.md`/`SKILL.md`-native universal core that reduces most IDE-specific files to thin, largely mechanical wrappers — given that Kramak is solo-maintained and the underlying tooling landscape is changing on a timescale of months, not years?

**Source note:** `sessions/T2-03-ide-ecosystem-scan.md` was not present in the workspace at the time of this spike (checked `/mnt/user-data/uploads`, `/mnt/transcripts`, and the full project tree — no matching file exists). Rather than block on that dependency, this report conducts the ecosystem scan fresh, current as of 2026‑08‑19, and treats itself as a supersede-or-merge candidate for the planned T2‑03 deliverable. Every factual claim below is sourced independently (see §7); none depend on the missing file.

## 2. Key Findings

*Evidence grades used inline: **[A]** primary source (vendor blog, official docs/repo, standards-body release); **[B]** well-corroborated secondary reporting (multiple independent outlets agree on the same facts/figures); **[C]** single-sourced, older, or general-knowledge claims used for context. Full rubric in §7.*

- **The universal-core bet is no longer speculative — it's already the substrate.** All 7 named tools read `AGENTS.md` either natively or via a documented one-line bridge, and the format now has multi-vendor, Linux Foundation–governed stewardship (the Agentic AI Foundation, founded Feb 2026 with Anthropic, OpenAI, and Block as founding contributors) rather than single-vendor control **[A]**. `SKILL.md` followed an almost identical path — Anthropic opened it as an independent standard in December 2025, and 30–40+ tools including 6 of Kramak's 7 named targets read it natively by mid‑2026 **[B]**.
- **Two of Kramak's 8 adapters suffered existential-level churn in the ~100 days before this report.** Windsurf was rebranded and re-engined into "Devin Desktop" by Cognition (agent core Cascade replaced by a Rust rewrite, "Devin Local"), and Roo Code — half of the combined "Cline/Roo Code" adapter — was shut down and archived by its own team on 2026‑05‑15, despite ~3M cumulative installs and ~24K GitHub stars **[A]**. Popularity did not predict survival in either case.
- **Momentum is concentrated in two tools that also happen to be stable; a third has momentum without stability.** Claude Code and Cursor combine large, fast-growing, high-satisfaction user bases with comparatively settled extensibility surfaces. Google Antigravity has comparable momentum (Gemini 3-backed, strong benchmark results, a major Google I/O relaunch) but is under a year old and has already replaced its own CLI and split into four product surfaces within six months **[B]**.
- **GitHub Copilot has the largest raw footprint but the weakest power-user affinity of the "big three."** ~20M+ users / 4.7M paid subscribers dwarfs Cursor and Claude Code by seat count, but developer-satisfaction surveys put it at 9% "most loved" versus Claude Code's 46% and Cursor's 19% **[B]** — a reach/depth mismatch that argues for broad, thin coverage rather than bespoke depth.
- **The comparable-ecosystem playbook is consistent: thin documented core + a community-stewardship layer for orphan-risk plugins, not exhaustive in-house coverage.** ESLint's own core team spun up a dedicated `eslint-community` GitHub organization specifically so that widely-depended-upon plugins "don't hold the wider community back by depending on a single person's GitHub or npm account" **[A]** — the exact bus-factor problem an 8-adapter, solo-maintained project already has.
- **Developers multi-home across tools rather than converging on one**, with independent surveys putting 59–70% of engineers using 2–4 AI coding tools simultaneously **[B]**. This cuts against pure consolidation: breadth of *coverage* still has real value, but that argues for cheap breadth (thin/Generic), not expensive breadth (8× deep adapters).
- **Market-share figures disagree by up to ~2x across sources for the same period** (e.g., Stack Overflow's Copilot figure of 51% vs. JetBrains' three-way split putting Copilot at 29%) **[B]** — a reason to treat absolute percentages in this report as directional, not authoritative, and to prefer Kramak's own adapter-activation telemetry once available (see §6).

## 3. Recommendation

**Adopt the `AGENTS.md`/`SKILL.md`-native universal core as Kramak's primary adapter architecture (Option 3), with deep, hand-maintained logic retained for exactly two targets — Claude Code and Cursor — layered on top of that core (a narrow, evidence-gated slice of Option 2). Google Antigravity is explicitly *not* placed in the deep tier at this time, despite the brief's proposed Tier‑1 grouping; it is a promotion candidate with a stated trigger (§5.5). Option 1 (deep-maintain all 8) is rejected outright.**

Concretely, for D‑005:

1. **Kramak's core investment shifts to generating a correct, well-scoped `AGENTS.md` + `SKILL.md` pair per project.** This is the asset that now transfers, at near-zero marginal cost, to Antigravity, Windsurf/Devin Desktop, Cline, GitHub Copilot, and Aider — all of which read one or both formats natively today.
2. **Claude Code and Cursor keep dedicated adapter code** that goes beyond the universal files: Claude Code's `@AGENTS.md` import line in `CLAUDE.md` (its documented, official bridge pattern, since Claude Code does not read `AGENTS.md` at the top level) plus skills/hooks/subagent wiring where it adds real value; Cursor's `.mdc` glob-scoped rule activation, which plain `AGENTS.md` cannot express. Both tools clear *both* bars this report uses to justify depth: high, corroborated momentum **and** a stable, documented extensibility surface.
3. **The other five named tools (Antigravity, Windsurf/Devin Desktop, Cline, GitHub Copilot, Aider) get the Generic/universal core plus a thin, mechanically-generated shim** that copies or symlinks the `AGENTS.md`/`SKILL.md` output into each tool's expected path (`.windsurf/rules/`, `.clinerules/`, etc.). This is templating, not judgment — it can be written once, covered by a contract test, and left alone.
4. **Roo Code is deprecated immediately**, not "monitored." It no longer exists as an independently maintained product (see §5.2). The current combined "Cline/Roo Code" adapter should be renamed to "Cline," with a documentation note on the Roo Code shutdown and its community successor paths (Cline itself, and the community fork "Kilo Code").

This is a deliberate departure from all three options as literally framed: it is not pure breadth (Option 1, rejected — unsustainable for a solo maintainer and already burned twice in 100 days), not the brief's literal Tier‑1 grouping (Option 2, modified — Antigravity does not yet clear the stability bar), and not a pure universal core with no differentiation (a stricter reading of Option 3, extended — Claude Code and Cursor earn kept depth on the evidence). See §4 for the case against each rejected alternative and §5.5 for the exact conditions under which Antigravity (or any Tier‑2/3 tool) would be promoted.

## 4. Alternatives Considered

**Option 1 — Maintain all 8 deep adapters.** Rejected. A solo maintainer cannot track 8 independently-evolving vendor roadmaps and also ship Kramak's own features. The evidence makes this concrete rather than theoretical: two of the eight adapters underwent existential change (rebrand + agent-core replacement; outright shutdown) in the ~100 days immediately preceding this report. Deep investment in either would likely have needed substantial rewriting or been wasted outright within two quarters. This option also has the worst ratio of maintenance cost to marginal value, since five of the eight targets already get most of their value from a well-formed `AGENTS.md`/`SKILL.md` pair alone.

**Option 2 as literally framed — Consolidate to Antigravity + Cursor + Claude Code (deep) + Generic.** Rejected in its inclusion of Antigravity at full depth *today*. Antigravity clears the momentum bar (Gemini 3 backing, strong SWE-bench results, a major I/O 2.0 relaunch) but not the stability bar: it is under a year old, has already replaced its own CLI once (Gemini CLI → Antigravity CLI, June 2026), split into four product surfaces within six months of the 2.0 relaunch, has documented enterprise-readiness and security-disclosure gaps, and requires a personal Gmail account that blocks most enterprise/Workspace deployments. Deep-adapting a moving target this early risks doing the work twice. This option, taken literally, also leaves value on the table: it doesn't capture the fact that Copilot, Cline, Windsurf/Devin Desktop, and Aider are *already* AGENTS.md/SKILL.md-native, so a "Generic" catch-all undersells how cheaply real coverage of those four is available.

**Option 3, strict reading — Universal core only, no tool-specific depth anywhere.** Rejected as too conservative. Claude Code and Cursor are not just popular; satisfaction and market data both indicate they carry a disproportionate share of Kramak's likely power-user base, and both expose real, documented capability (Claude Code's skills/hooks/subagents; Cursor's glob-scoped `.mdc` activation) that a plain `AGENTS.md` file structurally cannot express. Forgoing that last mile trades away cheap, durable differentiation for the two targets where it is most likely to be used and least likely to be wasted.

**A fourth option considered and not adopted: sunset the adapter-per-tool architecture entirely in favor of `AGENTS.md`/`SKILL.md` output only, with zero tool-specific code, including for Claude Code and Cursor.** This was rejected for the same reason as the strict reading of Option 3 above — it under-serves Kramak's two highest-value, most-stable targets for the sake of architectural purity.

### 5.2 Per-adapter notes

**Claude Code.** Anthropic's own product surface has grown from a CLI into CLI + VS Code/JetBrains extensions + desktop app + web + Slack, with a large, versioned documentation set covering skills, hooks, subagents, plugins, and MCP. It does **not** read `AGENTS.md` at the top level — this was verified directly (dropping an `AGENTS.md` into a Claude Code session with no `CLAUDE.md` produces no effect) — but Anthropic documents and recommends a one-line bridge: a `CLAUDE.md` whose first line is `@AGENTS.md`, importing the shared file and then appending any Claude-specific notes beneath it **[A]**. This is precisely the "thin wrapper over a universal core" pattern this report recommends generalizing — Anthropic has already built and documented it for its own flagship product. An open GitHub issue requesting native `AGENTS.md` support has accumulated thousands of reactions; if Anthropic ships it, Kramak's bridge-generation code becomes unnecessary and should be removed at that time (tracked in §6).

**Cursor.** Deprecated its original single-file `.cursorrules` in late 2024 in favor of `.cursor/rules/*.mdc` — a directory of glob-scoped, independently-activated rule files — while keeping the old file readable for compatibility. Cursor also now reads `AGENTS.md` natively, including nested subdirectory files, and documents a clear division of labor: `AGENTS.md` for portable, cross-tool instructions; `.mdc` for Cursor-specific fine-grained activation (path globs, "agent requested" vs. "always apply" modes) that `AGENTS.md` cannot express **[B]**. This is exactly the shape of value that justifies keeping a bespoke Cursor adapter: generate the shared file for portability, generate `.mdc` for the activation control a plain markdown file structurally lacks.

**Google Antigravity.** Launched November 18, 2025 as a VS Code-fork IDE built on Gemini 3; reported strong SWE-bench Verified results and rapid feature velocity **[B]**. Added `AGENTS.md` support (alongside its native `GEMINI.md`) in version 1.20.3 (March 2026), and adopted the Agent Skills (`SKILL.md`) standard around January 2026 **[B]**. At Google I/O 2026 (May 19), it relaunched as "Antigravity 2.0," splitting into four surfaces — IDE, desktop command center, a new Go-based CLI succeeding Gemini CLI, and a Python SDK — with the standalone Gemini CLI sunsetting for most users on June 18, 2026 **[B]**. Independent enterprise comparisons report no documented enterprise case studies for Antigravity as of mid-2026 (versus multiple named, quantified Cursor deployments) and note early security-disclosure issues and the lack of a Google Workspace (vs. personal Gmail) account path **[B]**. Net: a serious long-term contender that is not yet a safe deep-integration target.

**GitHub Copilot.** Distribution advantage from GitHub/Microsoft bundling gives it the largest raw user base of any tool in this set, but multiple developer-sentiment surveys place it well behind Cursor and Claude Code on satisfaction and power-user "most loved" scores **[B]**. It reads `AGENTS.md` as its own documented convention for agent-mode rules, so a thin/Generic adapter already covers its primary configuration surface; deep investment would mostly buy coverage of enterprise-billing and inline-completion behavior that is outside Kramak's likely scope.

**Windsurf → Devin Desktop (Cognition).** The most volatile entry in this set. Timeline: Codeium rebranded itself "Windsurf" pre-2025; a bidding war (OpenAI, Google) in mid-2025 ended with Google hiring away the founding team in a reverse-acquihire and Cognition (maker of Devin) acquiring the remaining company for a reported ~$250M in December 2025 **[A/B]**; on June 2, 2026, Cognition retired the Windsurf brand entirely via an over-the-air update, relaunching the product as "Devin Desktop" with a new default "Agent Command Center" view **[A]**; the original local agent, Cascade, reached end-of-life July 1, 2026, replaced by a full Rust rewrite, "Devin Local" **[A]**. Despite this churn, Devin Desktop's own documentation describes `AGENTS.md` as "the simplest way to add rules" and natively reads `SKILL.md` files, and it additionally reads Claude Code's `~/.claude/CLAUDE.md` and Cursor's rule formats for cross-tool interoperability **[A]** — the underlying openness this report is betting on has, if anything, strengthened through the acquisition. The risk is entirely about brand/product identity, not about format support.

**Cline.** An open-source VS Code extension (originally "Claude Dev") that has grown into a cross-IDE agent runtime, now also running inside JetBrains, Cursor, Windsurf/Devin Desktop, Zed, and Neovim, with a preview CLI **[B]**. Reads `AGENTS.md` (including a global `~/.agents/AGENTS.md` for cross-tool instructions) and `SKILL.md` natively, alongside its own legacy `.clinerules/` format kept for backward compatibility **[A]**. Recently added a paid tier ("ClinePass") and a plugin/skills marketplace, suggesting a sustainable, if modest, revenue base rather than pure volunteer maintenance.

**Roo Code.** Originally a late-2024 fork of Cline ("Roo Cline"); grew to ~3M cumulative installs and ~24K GitHub stars before its own team announced a sunset on April 20, 2026 and shut the extension down on May 15, 2026, redirecting users to Cline (its upstream project) and to "ZooCode," an independent community fork **[A — confirmed directly from the `RooCodeInc/Roo-Code` GitHub repository's own README]**. The team's stated reason was a strategic bet against IDE-based coding entirely, in favor of a Slack-first cloud agent ("Roomote"). This is the single cleanest evidence point in this report for why install counts and star counts are necessary but not sufficient signals for adapter investment.

**Aider.** A small, deliberately narrow, git-native, terminal-only tool maintained primarily by its original author with a large community contributor base; reported 40K+ GitHub stars and roughly biweekly releases as of mid-2026, still described by at least one industry tracker as a top-three terminal coding agent by daily active users **[C]**. It supports `AGENTS.md`. Its relative position has likely softened as Anthropic, OpenAI, and Google have all shipped officially-backed terminal agents with more resources behind them, but nothing in the research indicates Aider is at shutdown risk — it is a stable, low-maintenance-cost target precisely because it is small and disciplined.

**Generic.** Not a product but Kramak's own fallback — and, on this report's recommendation, the primary place new engineering effort should go. Every improvement to Kramak's `AGENTS.md`/`SKILL.md` generation quality (correct precedence handling, monorepo-aware nested-file emission, skill packaging) pays off across five to seven targets simultaneously rather than one.

### 5.3 Maintenance economics: lessons from comparable ecosystems

The multi-target-adapter problem is not new, and mature developer-tool ecosystems converge on a consistent pattern rather than reinventing one per project:

- **ESLint** defines a documented, stable plugin interface in its core and does not attempt to own most of its rule ecosystem directly. Where a widely-depended-upon community plugin risked going unmaintained (the classic single-maintainer bus-factor problem), the project did not try to absorb it into core; it created a separate `eslint-community` GitHub organization with its own small governance team, explicitly so high-value packages "don't hold the wider community back by depending on a single person's GitHub or npm account" **[A]**. This is a direct precedent for Kramak's community-adapter proposal in §5.6.
- **Oxlint** (a from-scratch, Rust-based reimplementation competing with ESLint) explicitly chose *not* to chase full plugin-ecosystem parity: internal maintainer guidance frames the goal as "support most of them, not all," because full compatibility would create "a similar burden on the [other project's] maintainers" and an open-ended support obligation for marginal adoption gains **[B]**. This mirrors this report's Tier‑1 cutoff logic: the marginal cost of the last few percent of coverage is disproportionate to its value.
- **EditorConfig** is the closest structural analogue to the recommended strategy: one small, universal, `.editorconfig` file defines formatting intent, and each editor ships only a thin reader/writer for it — the file format carries the complexity, not the per-editor integration. This is a well-established, long-stable pattern in the editor-tooling space **[C — general knowledge, not independently re-verified for this report, but not materially disputed]**.
- **pytest**'s plugin ecosystem (hundreds of third-party packages discovered via standard Python entry points) follows a similar community-stewardship shape, with a `pytest-dev` organizational umbrella absorbing some widely-used but originally single-maintainer plugins over time **[C — general knowledge]**.

The common thread: mature multi-target tools keep a small, stable, well-documented **contract** in core, push implementation of the long tail to the community under that contract, and reserve direct core-team ownership for the handful of integrations that are both high-value and high-stability. That is the structure this report recommends for Kramak.

### 5.4 `AGENTS.md` / `SKILL.md` feasibility assessment

Both formats have moved from "promising convention" to "governed standard" within the last eight months:

- `AGENTS.md` was proposed by OpenAI in August 2025, and donated to a new Linux Foundation body — the Agentic AI Foundation (AAIF) — in December 2025/February 2026, alongside Anthropic's Model Context Protocol and Block's `goose`, with Anthropic and Block as co-founding contributors **[A]**. Reported adoption figures (60,000+ repositories) appear consistently across independent trackers, though they likely share a common origin and should be read as directional **[B]**.
- `SKILL.md` (Agent Skills) was authored by Anthropic, launched inside Claude Code in October 2025, and released as an independent open standard on December 18, 2025. Microsoft and OpenAI shipped compatible support within 48 hours; by mid-2026, independent trackers count 30–40+ compatible tools, including Google Antigravity (adopted ~January 2026), Cursor, GitHub Copilot, and Cline **[B]**.
- **Coverage across Kramak's 7 named tools is close to complete**: Cursor, GitHub Copilot, Windsurf/Devin Desktop, Cline, and Aider all read `AGENTS.md` natively; Google Antigravity reads it natively since March 2026; Claude Code requires the one-line `@AGENTS.md` import bridge described in §5.2. `SKILL.md` coverage is slightly narrower but still spans Claude Code (native), Cursor, GitHub Copilot, Antigravity, Windsurf/Devin Desktop, and Cline.
- **Real gaps remain**, and a universal core does not eliminate all tool-specific work: precedence and scoping rules differ (nearest-file-wins directory nesting for `AGENTS.md`/`CLAUDE.md` vs. Cursor's source-tier resolution for `.mdc`), and fine-grained activation (glob-scoped, mode-scoped, or manually-invoked rules) is not expressible in plain `AGENTS.md` at all — hence the case for keeping Cursor's `.mdc` generation and Claude Code's richer feature wiring as genuine adapter work rather than folding everything into the Generic path.
- **A complementary, lower-level standard is emerging alongside these two**: the Agent Client Protocol (ACP), an open, Apache-2.0, JSON-RPC protocol for runtime communication between an editor and any compatible agent (analogous to the Language Server Protocol), has shipped in Devin Desktop and gained adoption signals from JetBrains, VS Code, GitHub, and Google **[B]**. ACP addresses a different layer — live agent-editor communication rather than static project instructions — and is too early to build against, but is worth tracking (see §6).

### 5.5 Deprecation triggers

| Trigger | Definition | Action | Precedent observed in this scan |
|---|---|---|---|
| **Vendor shutdown/EOL** | Tool's own maintainers announce discontinuation, archival, or sunset | Deprecate any bespoke adapter code within one Kramak release cycle; redirect docs to Generic and any named successor | Roo Code, shut down 2026‑05‑15 by its own team **[A]** |
| **Identity/engine replacement** | Rebrand, acquisition, or replacement of the core agent/engine a deep adapter targeted | Freeze new bespoke development for a 90-day observation window; downgrade to thin/Generic if compatibility isn't reconfirmed within that window | Windsurf → Devin Desktop, Cascade → Devin Local, June–July 2026 **[A]** |
| **Usage-share floor** | Tool's share of Kramak's own adapter-activation telemetry (or, absent telemetry, external survey data) stays below ~3–5% for two consecutive review cycles with no community maintainer volunteering | Downgrade from deep to thin tier | Not yet applicable — no target currently below floor, but this is the mechanism that would catch a slow fade rather than a sudden shutdown |
| **Config/extension-format churn** | A tool changes its own config file format or extension API in a breaking way more than once within 6 months | Yellow flag: shift toward thin/Generic even if the tool stays backward-compatible, since it signals an unsettled interface | Cursor's `.cursorrules` → `.cursor/rules/*.mdc` migration (2024) — noted as a caution even though Cursor stayed backward compatible and remains Tier 1 on other evidence |
| **Maintainer-bandwidth ratio** | A given deep adapter consumes disproportionate maintainer time relative to its measured usage share across 2 consecutive releases | Downgrade regardless of the tool's external popularity | Internal trigger — the one Kramak controls directly regardless of what the market does |
| **Promotion (inverse trigger)** | A Tier‑2/3 tool sustains usage share above the deep-tier threshold for 2 consecutive review cycles **and** shows no more than one breaking config/extension change in the prior 6 months | Promote to deep tier | Defines exactly how Google Antigravity could earn full Tier‑1 status — e.g., if it ships stable Workspace/enterprise account support and its CLI/surface set holds steady through two more quarterly reviews |

### 5.6 Community contribution specification

Goal: let third parties own long-tail adapters without any of them gating a Kramak core release.

1. **Publish a versioned Adapter Interface Contract.** A small, stable, documented interface (input: Kramak's internal project/instruction model; output: files at declared paths) — modeled on ESLint's plugin object interface. Community adapters implement against this contract, not against Kramak's internals.
2. **House community adapters in a separate namespace or repository** (e.g., a `kramak-community-adapters` org, mirroring `eslint-community`), each with a named, publicly-listed maintainer. Core releases never depend on these repositories building successfully.
3. **Gate community adapters with contract tests, not manual review.** A conforming adapter must pass a published test suite against the interface contract before being listed in Kramak's adapter directory; passing is necessary but Kramak core CI does not run third-party adapter suites as a release blocker.
4. **Define an explicit staleness policy.** If a listed adapter's contract tests start failing against a new Kramak core version and the listed maintainer doesn't respond within a stated window (e.g., 6 weeks), the directory listing is flagged "unmaintained" (not deleted) and, after a further window with no response, archived — the same non-punitive "don't block the ecosystem, don't silently keep serving stale info" logic ESLint applied to orphaned plugins.
5. **Provide a scaffold that makes "thin wrapper over `AGENTS.md`/`SKILL.md`" the path of least resistance.** Since most of the real value now lives in Kramak's universal-core generation logic rather than in any individual adapter, a new community adapter for, say, a niche editor should typically be a few dozen lines of path-mapping code plus tests — deliberately low-effort to contribute, by design, following Oxlint's "aim to cover most, not all" philosophy from §5.3.
6. **Use a lightweight discovery/hint mechanism** (comparable to plugin-hint patterns already used elsewhere in this ecosystem) so community adapters are surfaced to users without being bundled into Kramak's own release artifact.

## 6. Open Questions & Risks

- **Will Anthropic ship native `AGENTS.md` support in Claude Code?** An open, high-engagement GitHub issue requests this; if shipped, Kramak's `@AGENTS.md`-bridge-generation code for Claude Code becomes redundant. *Revisit: check at each quarterly review; no urgent action needed today since the current bridge pattern is official and documented.*
- **Does Google Antigravity stabilize enough to earn Tier‑1 status?** Momentum is real; stability is not yet established (see §5.5 promotion trigger). *Revisit: quarterly at minimum — independent enterprise-tooling reviewers in this space are recommending the same quarterly cadence for this specific tool — plus immediately upon any further major version change or account-model announcement.*
- **Does Cognition preserve `AGENTS.md`/`SKILL.md` support and general openness in Devin Desktop as the product matures past its rebrand?** Current signals are strong (ACP support, explicit cross-tool file reading), but the product's roadmap is now Cognition's, not the original Windsurf team's. *Revisit: 90 days, per the identity-replacement trigger in §5.5, or on the next major Devin Desktop release.*
- **Will the AAIF's planned `AGENTS.md` v1.0 stable behavioral specification (on its public roadmap) change precedence, monorepo, or activation semantics** in ways that affect Kramak's generation logic? **[B — sourced to AAIF roadmap commentary, not an AAIF primary document directly reviewed for this report]**. *Revisit: when v1.0 ships, or at the next scheduled review, whichever comes first.*
- **Is the Agent Client Protocol (ACP) worth building against yet?** It addresses a different layer (runtime agent-editor communication) than `AGENTS.md`/`SKILL.md` (static instructions) and could eventually reduce adapter work further, but adoption is early. *Revisit: 6 months, non-urgent.*
