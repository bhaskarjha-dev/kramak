# Kramak — Bootstrap Procedure

> First-time setup for a new or existing project. This runs ONCE, then the regular Plan-Execute-Audit loop takes over.

---

## Scenario Detection

When this procedure is invoked, determine which scenario applies:

### Scenario 1: Continuing Project
**Check:** Does `.agents/pipeline/state.json` exist?
→ **YES:** This project already has a pipeline. Read state.json and follow the procedure for `state.phase`. **Do not re-bootstrap.**

### Scenario 2: Existing Project With Context
**Check:** Does `.agents/AGENTS.md` exist? (or CLAUDE.md, .cursorrules, README.md with substantial content)
→ **YES:** This project has context but no pipeline.

**Actions:**
1. Read AGENTS.md (or equivalent) to understand the project
2. Scan the workspace: `ls`, check for package.json/Cargo.toml/go.mod/pyproject.toml/etc.
3. Detect the toolchain (see Toolchain Detection below)
4. Create `.agents/pipeline/` directory structure
5. Create `state.json` from template with `phase: "planning"`
6. Create `INBOX.md` from template
7. Create `HUMAN-TASKS.md` from template
8. Create empty `queue/`, `active/`, `done/`, `failed/` directories
9. Tell the user: "Pipeline initialized. Starting planning phase."
10. Proceed to PLANNER.md STEP 1

### Scenario 3: Existing Project Without Context
**Check:** Are there source code files in the workspace? (*.ts, *.py, *.go, *.rs, *.java, etc.)
→ **YES:** Project exists but has no agent context.

**Actions:**
1. Scan the workspace structure (list directories, key files)
2. Read README.md if it exists
3. Detect the toolchain (see Toolchain Detection below)
4. Auto-generate `.agents/AGENTS.md` with:
   - Project name (from package.json name, Cargo.toml, go.mod, or directory name)
   - Detected tech stack
   - Directory structure overview
   - Build/test/lint commands
   - A note: "Auto-generated by Kramak. Please review and refine."
5. Create `.agents/pipeline/` directory structure (same as Scenario 2)
6. Tell the user: "Pipeline initialized with auto-detected project context. Please review .agents/AGENTS.md."
7. Proceed to PLANNER.md STEP 1

### Scenario 4: New Project With Requirements
**Check:** Are there requirement docs, PDFs, specs, or data files but no source code?
→ **YES:** This is a new project with provided requirements.

**Actions:**
1. Read all available requirement files
2. Extract project intent, features, constraints
3. Generate `.agents/AGENTS.md` with extracted requirements
4. Create `.agents/pipeline/` directory structure
5. Set `state.json` with `phase: "planning"` 
6. Proceed to PLANNER.md STEP 1 — the first batch will scaffold the project

### Scenario 5: Empty Workspace
**Check:** Workspace is empty or nearly empty.
→ **YES:** No code, no docs, nothing to work from.

**Actions:**
1. Tell the user: "Empty workspace detected. What are we building? Please describe the project or add requirement files to the workspace."
2. Create `.agents/pipeline/` directory structure with `phase: "waiting"`
3. Create `INBOX.md` — tell the user to put project description here
4. STOP. Wait for user input.

## Toolchain Detection

Scan the workspace root for these files to auto-detect the build/check commands:

| File Found | Ecosystem | Build Command | Check Commands |
|-----------|-----------|---------------|----------------|
| `package.json` + `pnpm-lock.yaml` | Node.js (pnpm) | `pnpm install` | `pnpm tsc --noEmit` (if TypeScript), `pnpm lint` |
| `package.json` + `package-lock.json` | Node.js (npm) | `npm install` | `npx tsc --noEmit` (if TypeScript), `npm run lint` |
| `package.json` + `yarn.lock` | Node.js (yarn) | `yarn install` | `yarn tsc --noEmit` (if TypeScript), `yarn lint` |
| `Cargo.toml` | Rust | `cargo build` | `cargo check`, `cargo clippy` |
| `go.mod` | Go | `go build ./...` | `go vet ./...`, `golangci-lint run` |
| `pyproject.toml` / `requirements.txt` | Python | `pip install -e .` | `mypy .`, `ruff check .` |
| `build.gradle` / `pom.xml` | Java/Kotlin | `./gradlew build` / `mvn compile` | `./gradlew check` / `mvn verify` |
| `Gemfile` | Ruby | `bundle install` | `bundle exec rubocop` |

**Additional detection:**
- If `tsconfig.json` exists → TypeScript project, add `tsc --noEmit` to checks
- If `biome.json` or `biome.jsonc` exists → add `biome check` to checks
- If `.eslintrc*` exists → add `eslint` to checks
- If `prettier.config*` or `.prettierrc*` exists → add `prettier --check` to checks
- If `turbo.json` exists → monorepo, use `turbo` commands
- If `nx.json` exists → Nx monorepo

**Store detected commands** in `state.json` under `toolchain`:
```json
{
  "toolchain": {
    "packageManager": "pnpm",
    "buildCommand": "pnpm install",
    "checkCommands": ["pnpm tsc --noEmit", "pnpm biome check"],
    "devCommand": "pnpm dev",
    "detected": true
  }
}
```

## Git Initialization

If the workspace is not a git repository:
1. Run `git init`
2. Create `.gitignore` appropriate for the detected ecosystem
3. Run `git add .` and `git commit -m "chore: initial commit"`

If it IS a git repo:
1. Check current branch
2. Record it in `state.json`

---

## Output

After bootstrap, the workspace should have:
```
.agents/
├── AGENTS.md              ← Project context (auto-generated or pre-existing)
├── pipeline/
│   ├── state.json         ← Initial state (phase: "planning")
│   ├── INBOX.md           ← Empty inbox with format guide
│   ├── HUMAN-TASKS.md     ← Empty human tasks file
│   ├── queue/             ← Empty (planner will populate)
│   ├── active/            ← Empty
│   ├── done/              ← Empty
│   └── failed/            ← Empty
```
